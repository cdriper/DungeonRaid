# Reconstructed game core

Portable C++17 + CMake, ported from our own Ghidra decompilation and disassembly of the original `lib/armeabi-v7a/libDungeonRaidJni.so` and checked function by function against the original running in an emulator harness (the `difftest_*.py` differential tests and `check.py`). Used by the hosts in `platform/` and by `tests/`.

**About the tooling:** the recompilation used an emulator harness (`harness/`), reverse-engineering data and generator scripts (`re/`: Ghidra exports, `re/structs/*.json`, `re/scripts/*.py`) and the original APK contents (`legacy/`). They are part of the development history and are not published in this repository. Mentions of them below (generated files, `difftest_*.py`, "the tests") are kept as a record of how each part was made and checked. In this repository the check is the golden replay test (`tests/`, see the top-level `README.md`).

## Porting rules

- Port from the **disassembly** where precision matters; the decompiler hides bit casts and operation order (e.g. `RandUnitF` reinterprets bits, it doesn't convert).
- **Bit-exact floats:** the original is single-precision VFP code whose multiply-adds (`vmla`) are not fused. Keep the operation order of the original, one rounding per operation, and keep FP contraction off (`-ffp-contract=off`, MSVC `/fp:precise`; set in `CMakeLists.txt`).
- Each function carries its Ghidra address in the header comment; behaviour notes go next to the code.
- Names follow the original symbols (`RandI`, `GameState::WriteInteger`, ...); member names follow `re/structs/*.json`.
- **`char` is unsigned on ARM** (signed on x86/MSVC): wherever the original uses a `char` as a number (glyph lookups), cast to `unsigned char`.
- Files are opened in binary mode (`"rb"`): bionic's `"r"` doesn't translate CRLF, Windows text mode would.
- **No hooks or test seams left** (removed 2026-11-12): during the incremental port, calls into unported code went through a hook table (`g_unportedGameCalls`), and the harness's class tests overrode some Game methods through `DR_TEST_SEAMS`. Everything is ported and nothing in this repo used either; they are in git history. The core has no `#if` apart from `#pragma once`.
- Constants: take the exact float bit pattern from the disassembly, not the decompiler's rounded display (`0x3e1ccccd` is 0.153125 = 49/320, not 0.153). Check that each decimal literal round-trips to those bits: some originals are not the nearest float to their 'obvious' value (`Process` uses 0x3d75c290 = `0.060000002f`, while `0.06f` is 0x3d75c28f).
- Quirks of the original stay (documented next to the code), e.g. `Label::SetText` growing its Quad vector beyond what it uses, `Interpolate`'s opposite directions.

## Known, accepted differences

- **No JNI:** the original's 143 SWIG JNI entry points (`dr_jni.cpp`, generated by `re/scripts/gen_jni.py`) were removed on 2026-11-12 with the Kotlin shell; the C++ hosts call the Game directly.
- **Drawing call names:** the core calls `sdlDrawArrays`, `sdlBindTexture`, ... where the original calls `glDrawArrays`, `glBindTexture`, ... (renamed 2026-11-12; same arguments and order, so the recorded traces still compare under the GL names).

- **NaN sign:** an invalid operation (`inf - inf`) gives `0x7fc00000` on ARM VFP and `0xffc00000` on x86 SSE. The game never inspects NaN bits; the differential tests treat these two default NaNs as equal (`is_default_nan` in `difftest_ui.py`). Any other NaN-shaped word is compared exactly: an RGBA colour with alpha 0xff reads as a NaN, and until 2026-11-08 the tests let such colours pass unchecked.
- **Time source:** the original divides `clock()` (process CPU time on Android) by 1e6. The port reads a microsecond counter through `SetClockSource` (default: a monotonic wall clock); the harness installs a fake clock.
- `RandUnitF` in the original stores its bit pattern in a global (`0x00089ad0`) before reloading it as a float; the port uses a local `memcpy`. Nothing else reads that global.
- `CharacterClass::Validate` is meant to drop surplus replacement skills but starts its counter from `GetReplacementSkillCount()` instead of `GetReplacementSkillsAllowed()`, so it never does; kept as is.
- Uninitialised memory stays uninitialised where it is data (e.g. a new `GameState` buffer), as in the original. Uninitialised scalar fields and locals are zeroed in the port: `Font()` leaves texture, line height and base unset in the original, `Upgrade()` the icon UVs and name, `CharacterClass()` everything but the vectors, statistics and skill pool; `Font::LoadFont` works with uninitialised locals when a line fails to parse (e.g. an `info` line longer than 255 characters, which `fgets(256)` splits), i.e. undefined behaviour, so only the defined part is compared there.
- `Font::SplitLines` crashes in the original on a word wider than the line (`memcpy` with a negative length); the port pushes an empty line instead. No game text is that long.
- `ItemUpgrade::GetRandomStat` for an unknown item type (>= 5) has no candidates and returns a leftover counter, not a stat; `GetDescription` then reads past `g_upgradeDescriptions` (undefined behaviour). The game only uses types 0..4; the tests skip that combination. Out-of-range prefix/name indices in `Item::Deserialise1/2` likewise read past the name lists in both.
- `Item()`/`ItemUpgrade()` leave most scalar fields uninitialised in the original; the port zeroes them. `Item::MakeStatLabels` uses a static 128-byte text buffer as the original (0x00089484).
- `Skill()` and `Arrow()` leave most fields uninitialised in the original; the port zeroes them. `Skill::Initialise`/`Deserialise` print the level into small static buffers in the original (0x000896cc / 0x000896c8, the latter only 4 bytes); the port uses a local buffer (not observable).
- `Arrow::AddVertex` has no bounds check (as in the original); the tests stay within 0..0x11f.
- `FoldoutMenu`: the original's constructor leaves the selection, the scroll index and the animation fields unset (0 in the port), and `Menu`'s vertex array uninitialised (zeroed in the port). The shop's scroll offer skips skill type t when the word at Game+0xc358+4t is non-zero, meant as `m_skills[t]` but reading past the 4 slots into the fields that follow (skill count, chain counts, flags, the life leech SimpleLabel); the port rebuilds those words from its fields, counting padding bytes as 0 (fresh heap memory in the original). With no scroll candidate at all the original indexes a null vector and crashes; the port skips the scroll's skill. Stale bytes the original leaves in reused offer objects (after a name's NUL, unused stat texts, a real skill's stat-choice fields and vice versa) are not compared.
- `difftest_game.py` closes the fold-out menu before a new game (the game cannot start one with the menu open); otherwise the upgrade offers' item pointers dangle once `InitNewGame` replaces the items, in both.
- **Game test baseline:** both sides boot through the real `Game::Start` (its screens draw cosmetic random numbers; since slice 4f the port draws the same ones, so no RNG stream is copied any more). The original leaves the bytes after an item's name uninitialised (stale heap data); the test compares names up to their NUL. A token's value (0x98) is set only for mana and damage tokens and left uninitialised otherwise; a mana token without a skill to charge stops before its direction, speed and distance (0x80..0x97) are set (not compared in these cases).
- **powf, cosf, sinf:** the original calls bionic's libm (`powf(t, 5)` in `ProcessAttack`; `cosf`/`sinf` in `Particles`); the emulator computes them in double and rounds to float, and the port's `PowF`/`CosF`/`SinF` do the same. Bionic's are correctly rounded in practically all cases, which this matches; a last-bit difference on a device is possible in rare cases and only affects cosmetic values (a label's scale, particle positions), never the random streams (the number of draws does not depend on them).
- **Effect pools:** a new slot of the SimpleLabel and Particles pools is a copy of a freshly constructed, mostly uninitialised object in the original (stale stack bytes); the port's new slots are zeroed. Particles' Initialise sets every field; for SimpleLabels the test ignores the vertices and glyphs beyond the glyph count.
- **NaN sign in logged calls:** float arguments in the call logs are compared with all NaN patterns equal (same rule as above).
- **Float-to-int conversion:** ARM's `vcvt.s32.f32` saturates out-of-range values (NaN -> 0); a C++ cast is undefined there (x86 gives INT_MIN). Wherever a converted value can be out of range the port uses `FloatToIntArm`: `RandI` (`RandI(INT_MAX, INT_MAX)` computes 2^31), `Tile::GenerateStats` (difficulty base 0 divides by sqrt(0)) and the other Tile conversions.
- `Tile()` leaves most fields (incl. the countdown label pointer) uninitialised in the original; the port zeroes them. The destructor does not delete the labels (`DeleteLabels` does), copies share them, as in the original. Tile's text helpers print into static buffers in the original (0x00089758, 0x00089768); the port uses local buffers.
